# ADR-0012 OmniRoute 운영 시작 절차

| 항목 | 값 |
|---|---|
| 결정일 | 2026-10-03 |
| 결정자 | Philip |
| 상태 | 확정 |

## 배경

재부팅 뒤 데이터 폴더를 지정하지 않아 운영 설정이 사라진 것처럼 보인 사건이 있었다.
FAIL-2026-1003-001 과 FACT-042 참조.
상태 점검만으로 정상이라고 판단한 것이 원인의 한 축이었다.

## 결정

실험실은 OmniRoute 운영 환경을 쓰기 전에 아래 순서를 따른다.

| 순서 | 단계 | 확인할 것 |
|---|---|---|
| 1 | 버전 | 쓸 실행본과 버전 |
| 2 | 데이터 폴더 | 운영용 storage.sqlite 가 든 정확한 데이터 폴더 |
| 3 | 라우터 | 고정된 host 와 port 로 시작 |
| 4 | 상태 점검 | 상태가 정상인지 |
| 5 | 제공자 | 필요한 제공자 연결이 있는지 |
| 6 | 콤보 | 쓸 콤보가 있는지 |
| 7 | 짧은 시험 | 실제 작업 전에 짧은 요청을 한 번 보낸다 |
| 8 | 로그 | 실제 콤보, 제공자, 모델, 상태 코드를 확인한다 |
| 9 | 실제 작업 | 위를 통과한 뒤 시작한다 |

- 상태 점검이 정상이라는 것만으로 정상 판정을 끝내지 않는다.
- 시작 화면의 콤보 이름만 보고 준비가 끝났다고 판단하지 않는다. FACT-044 참조.

## 랩별 경로

| 랩 | 워크스페이스 | 시작 | 콤보 |
|---|---|---|---|
| LAB-A | LAB-A 워크스페이스 | claude-production | claude-production-v1 |
| LAB-B | LAB-B 워크스페이스 | codex-production | codex-production-v1 |

두 랩은 서로의 워크스페이스를 읽지 않는다. 공통 운영 지식만 이 도서관으로 나눈다.

## 지켜야 할 것

- 설정이 사라져 보이면 새로 만들기 전에 어느 storage.sqlite 를 쓰고 있는지 먼저 확인한다.
- 출력이 시작된 turn 안에서 제공자가 바뀌지 않는 경우가 있다. 세션을 끝내거나 콤보를 바꾸지 않고
  새 메시지로 이어간다. FACT-044 참조.
- 제공자의 운영 가치는 최근 실제 로그로 판단한다. FACT-043 참조.
- 제공자 순서 변경과 제외, 콤보 수정, API 키와 인증 변경은 Philip 의 명시적 승인이 있을 때만 한다.

## 기존 원칙과의 관계

FACT-041 과 ADR-0011 의 원칙은 그대로다. 이 문서는 그것을 바꾸지 않고
시작과 복구와 실행 중 전환 사례를 더한 것이다.
