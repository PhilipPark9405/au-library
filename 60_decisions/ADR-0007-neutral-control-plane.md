# ADR-0007 중립 Control Plane

| 항목 | 값 |
|---|---|
| 결정일 | 2026-09-21 |
| 결정자 | Philip |
| 상태 | 확정. 구축 전 |

## 결정된 것

1. 네 실험실의 전면 API 전환은 하지 않는다. 기존 구독을 유지하며 새 API 비용을 만들지 않는다.
2. 중립 Control Plane 하나를 두고, 네 실험실은 각자 독립적으로 실행한다.
3. Control Plane 은 Philip 소유의 기존 Railway Hobby 계정에 새 프로젝트로 올린다.
4. 구현은 LAB-A 가 맡는다. LAB-A 는 중립 소프트웨어의 제작자이며 다른 실험실을 지휘하지 않는다.

## 1단계 기능

| 기능 | 내용 |
|---|---|
| 승인 | 승인 요청을 텔레그램 버튼으로 받고 결과를 기록한다 |
| 현황판 | 네 실험실의 작업 상태를 한곳에 보여준다 |
| 자원 예약 | 공유 자원 신청과 배분 상태를 기록한다. ADR-0006 참조 |
| 도서관 갱신 알림 | 도서관의 최신 커밋이 바뀌면 알린다 |

1단계는 이 네 가지로 한정한다. 기능을 늘리려면 Philip 승인을 받는다.

## Control Plane 이 하지 않는 것

- 실험실의 워크스페이스, 코드, 프롬프트, 설계서를 읽지 않는다.
- AI 모델을 호출하지 않는다.
- 도서관에 쓰지 않는다. 최신 커밋 확인만 한다.
- 도서관 내용을 따로 저장하지 않는다. 도서관의 정본은 GitHub 저장소 하나다. 헌장 규칙 4 참조.
- 별도 데이터베이스 서비스를 두지 않는다. 기록은 파일로 남긴다.

Railway 서버는 Philip PC 의 실험실 워크스페이스에 접근할 수 없다. ADR-0005 의 상호 접근 금지가 구조로 유지된다.

## 텔레그램 구성

| 대상 | 구성 |
|---|---|
| 실험실별 봇 | Philip 과 1:1 대화. 표시명은 ADR-0006 |
| Control Room | Philip 전용 방. 중립 Status Bot 하나만 둔다 |

- 실험실 봇을 Control Room 이나 공동 방에 넣지 않는다.
- 실험실 봇의 Bot-to-Bot Communication Mode 는 켜지 않는다.
- 각 실험실 봇의 운영 방식은 각 실험실이 설계서에 정한다.
- Status Bot 의 표시명은 Philip 이 정한다.

## 실험실 쪽 연결

유료 API 를 쓰지 않으므로 Control Plane 이 실험실을 호출하지 않는다.
각 실험실은 기존 구독에 포함된 로컬 실행 수단이 있는지 설계서에 밝힌다.
그런 수단이 없는 실험실의 현황과 승인 요청은 Philip 이 Control Room 에 등록한다.

## 코드와 배포

- 코드는 au-library 와 별개의 비공개 저장소에 둔다. 저장소는 Philip 소유다.
- Railway 는 그 저장소에서 배포한다.
- 토큰은 Railway 의 Variables 에만 둔다. 코드와 저장소에 넣지 않는다.

## 비용

기존 Hobby 계정의 포함 사용량 안에서 운영하는 것을 목표로 한다.
금액은 헌장 4절에 따라 도서관에 적지 않는다.
사용량 상한은 걸지 않는다. 상한에 닿으면 같은 계정의 다른 프로젝트도 멈출 수 있다. 대신 사용량 알림을 쓴다.

## ADR-0001 과의 관계

ADR-0001 은 도서관의 구축과 동기화에 관한 결정이다. Control Plane 은 도서관이 아니며 도서관을 읽기만 한다.
ADR-0001 이 도서관 대안으로 기각한 Railway 와 PostgreSQL 중앙 관리와는 목적이 다르다.

## 근거

네 실험실 모두 전면 API 전환에 반대하거나 보류했다. 네 실험실 모두 중립 Control Plane 과 실험실 독립 실행에 동의했다.
기존 Railway 계정을 쓰면 새 비용 없이 상시 가동되며, Philip PC 가 꺼져도 승인과 현황판이 멈추지 않는다.

## 재검토 조건

- 사용량이 포함 사용량을 계속 넘는 경우
- 1단계 기능으로 Philip 의 전달 부담이 줄지 않는 경우
