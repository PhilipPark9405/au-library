# ADR-0001 구축 담당과 저장소 형태

| 항목 | 값 |
|---|---|
| 결정일 | 2026-09-19 |
| 결정자 | Philip |
| 상태 | 확정 |

## 결정된 것

1. 중앙 라이브러리의 구축과 유지는 Claude Code가 맡는다.
2. 저장소는 GitHub Public Repository `au-library` 하나로 한다.
3. 자동 동기화(GitHub Actions, cron)는 v1에서 켜지 않는다.
4. 승계 1순위는 Gemini CLI로 둔다.

## 권한 범위

| 주체 | 권한 |
|---|---|
| Philip | 소유자. 채택 판단, 최종 커밋 승인, 헌장 개정 |
| Claude Code | 파일 작성, 형식 검증, 커밋 대행. 내용 채택 판단 권한 없음 |
| 4개 실험실 | 읽기. 표준 양식에 맞춘 제출 |

Claude Code의 구축 역할은 일회성이다. v1 구축이 끝나면 Claude는 LAB-A로 복귀한다.
이후 유지 작업은 커밋 대행에 한정된다.

## 근거

- Claude Code는 파일 생성과 git 조작이 한 도구 안에서 이어진다. 사람이 파일을 옮기는 중간 단계가 없다.
- Claude Pro 구독에 Claude Code 사용이 포함되어 추가 과금이 없다.
- Public 저장소는 GitHub Free에서 무료이고, 인증 없이 웹에서 열람된다. 다섯 개 런타임이 같은 URL을 읽는다.
- 자동 동기화 스크립트는 실패 시 도서관 전체를 멈추게 한다. 파일 수정 빈도가 주 단위이므로 수동 커밋으로 충분하다.

## 대안과 기각 사유

| 대안 | 기각 사유 |
|---|---|
| Private Repo + Drive 미러 | 웹 기반 실험실이 Git을 읽지 못해 미러가 필요해진다. Public이면 미러 자체가 불필요하다 |
| Railway + PostgreSQL 중앙 관리 | 어떤 실험실도 DB를 직접 읽지 못한다. 단일 장애점이 된다 |
| 실험실별 저장소 4개 | 규격이 갈라진다. 같은 사실이 네 벌로 쌓인다 |

## 재검토 조건

- 저장소 공개로 인한 문제가 실제로 발생한 경우
- 파일 수정 빈도가 주 3회를 넘어 수동 커밋이 부담이 된 경우
- LAB-A의 채팅 환경은 저장소 조회에 제약이 있다. FAIL-2026-0919-005 참조. 커밋 결과 검증은 Philip이 직접 수행한다.
