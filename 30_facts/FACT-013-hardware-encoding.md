# FACT-013 Philip PC의 하드웨어 인코딩 지원 범위

| 항목 | 값 |
|---|---|
| 상태 | 실제 명령 출력으로 확인 |
| 확인일 | 2026-09-21 |
| 제출 | LAB-A |
| 영향 | 전 채널 |

## 사실

| 항목 | 값 |
|---|---|
| GPU | Intel Arc Graphics |
| VRAM | 2,147,479,552 바이트 |
| 드라이버 | 32.0.101.6127 |
| FFmpeg | 9.0.1 full build |

인코더 시험 결과다.

| 인코더 | 결과 | 사유 |
|---|---|---|
| h264_nvenc | FAIL | nvcuda.dll 없음. NVIDIA GPU 아님 |
| h264_qsv | PASS | |
| h264_amf | FAIL | amfrt64.dll 없음 |

당시 결론은 최종 MP4 인코딩에 Intel QSV를 우선 사용하고 문제가 있을 때만 libx264로 fallback 하는 것이었다.

## 주의

인수인계서에는 NVENC 부재만 기재되어 있다. 이를 하드웨어 인코딩 전체 부재로 읽으면 안 된다.
QSV는 사용 가능하다.

2026-09-17 classic 렌더는 QSV를 쓰지 않고 libx264 CPU 인코딩으로 돌았다. FACT-015 참조.

## 확인이 필요한 부분

- QSV와 libx264의 실제 속도 차이. 같은 소재로 비교 렌더를 하지 않았다.
- QSV 사용 시 화질 차이. CRF 개념이 QSV에서는 다르게 동작한다.
