# FACT-004 Moonlight Classic 롱폼의 음원 소요량

| 항목 | 값 |
|---|---|
| 상태 | 2026-09-21 재정정. 실제 다운로드 수 반영 |
| 확인일 | 2026-09-21 |
| 제출 | LAB-A |
| 영향 채널 | classic |

## 사실

- Moonlight Classic 롱폼 1편은 최소 1시간이다. 상한은 정하지 않는다.
- 곡을 이어 붙인 플레이리스트 형식이다.
- 목표 길이에 닿을 때까지 같은 곡 묶음을 반복한다.
- 곡 수는 롱폼 길이와 무관하다. 한 세트를 확보한 뒤 반복 횟수로 길이를 맞춘다.
- 한 곡을 길게 늘여 한 편을 채우는 방식이 아니다.

## 실제 제작 구조

2026-09-17 MC-UL-001 기준이다.

| 항목 | 값 |
|---|---|
| 곡 세트 | 14곡. MC001-T01 ~ MC001-T14 |
| 목표 길이 | 10,800초 |
| 크로스페이드 | 2,500ms |
| 반복 | 3패스 |
| 산출물 | MC-UL-001_final_3h.wav 2,966MB |

반복 순서는 고정이다.

| 패스 | 순서 |
|---|---|
| 1 | 원래 순서 |
| 2 | 홀수 번째, 그다음 짝수 번째 |
| 3 | 짝수 역순, 그다음 홀수 역순 |

곡 사이는 크로스페이드로 잇고 전체에 페이드인 2.5초, 페이드아웃 7초를 적용한다.
순서가 고정이라 같은 입력이면 같은 결과가 나온다.

## 다운로드 소요량

| 항목 | 값 |
|---|---|
| 한 세트 곡 수 | 14. config/tracks.json 기준 |
| 2026-09-17 실제 다운로드 | 18곡. Philip 확인 |
| 산출물 폴더 구성 | 9개 제목, 각 2버전 |

한 세트 곡 수와 실제 다운로드 수는 다르다. 14는 한 편에 들어가는 곡 수이고 18은 실제로 쓴 다운로드다.
18개 파일과 tracks.json 14곡의 대응 관계는 확인되지 않았다.

롱폼 길이를 늘려도 다운로드는 늘지 않는다. 반복 횟수만 늘어난다.

보유 18곡은 다음 classic 편에 재사용할 수 있다. 재사용하면 신규 다운로드는 0이다.

## 정정 내역

2026-09-19 초판은 롱폼 길이를 곡당 3.3분으로 나누어 곡 수를 산정했다.
1시간 18곡, 2시간 36곡, 3시간 54곡이며 다운로드도 같은 수라고 적었다.

이 산정은 실제 제작 방식과 다르다. 반복 구성을 고려하지 않았다.
2026-09-21 1차 정정은 한 세트 곡 수 14를 다운로드 수로 적었다.
같은 날 Philip이 실제 다운로드가 18곡임을 확인해 다시 정정했다.
곡 수와 다운로드 수를 구분한다.

## 확인이 필요한 부분

- 곡당 평균 길이 실측값.
- 에피소드마다 곡 세트를 새로 만드는지, 기존 세트를 재사용하는지.
  MC-UL-001이라는 project_id 체계로 보아 에피소드 단위로 보이나 확정되지 않았다.
- 같은 곡을 3회 반복한 롱폼이 유튜브 반복 콘텐츠 정책에 저촉되는지.
- 18개 파일과 tracks.json 14곡의 대응 관계. 3시간 마스터에 실제로 들어간 곡 목록은
  output/audio/masters 폴더에서 확인할 수 있으나 아직 조회하지 않았다.
