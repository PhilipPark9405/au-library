## 데이터 폴더를 가리키는 변수 이름

`DATA_DIR` 이다. 앞에 제품 이름을 붙인 다른 이름은 듣지 않는다.
이름을 틀리면 조용히 기본 폴더가 열린다. 오류가 나지 않는다.

## 배치 파일에서 다른 배치를 부를 때

전역 명령이 배치 파일인 경우, `call` 없이 부르면 앞서 설정한 환경 변수가 전달되지 않는다.
화면에는 설정값이 제대로 찍히는데 실제로는 기본값으로 서버가 뜬다.

```
call omniroute serve --port %PORT% --no-open --log
```

2026-10-05 에 이것 때문에 기본 데이터베이스가 열렸고, 거기에 변경이 적용됐다.

## 시작 스크립트가 비어 있어도 아무 일도 없다

0바이트 배치 파일을 실행하면 오류 없이 그냥 끝난다.
실행했는데 아무 반응이 없으면 파일 크기부터 본다.
2026-10-06 에 전날 만들어 검증까지 마친 시작 스크립트가 0바이트가 돼 있었다.
무엇이 지웠는지는 unknown 이다.

## CLI 명령은 서버가 아니라 데이터베이스를 직접 연다

`providers list` 나 `combo list` 같은 명령은 서버를 거치지 않고 데이터베이스를 직접 읽는다.
그래서 서버가 올바른 데이터베이스로 떠 있어도 이 명령들은 비어 보일 수 있다.

| 확인하려는 것 | 봐야 할 곳 |
|---|---|
| 서버가 어느 DB 를 쓰는가 | 서버 창의 시작 로그 |
| 제공자와 콤보가 있는가 | 대시보드 |
| CLI 로 보려면 | 명령 전에 `DATA_DIR` 을 같이 준다 |

## 운영 데이터는 임시 폴더에 두지 않는다

임시 폴더는 정리하다 날아간다. 운영 데이터베이스는 따로 둔 폴더에 보관한다.

## 비용 화면의 금액은 실제 청구가 아니다

정액제 구독으로 쓴 요청도 "API 로 썼다면 이만큼" 으로 환산해 표시된다.
화면에도 그렇게 적혀 있다. 실제 지출은 각 제공자 계정에서 봐야 정확하다.
2026-10-05 기준 30일 표시액의 대부분이 구독 추정치였고,
라우팅 효율성 화면의 대체 요청은 1,541건 중 0건이었다.
