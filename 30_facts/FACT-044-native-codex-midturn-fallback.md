# FACT-044 출력이 시작된 turn 안에서는 제공자를 바꾸지 못한다

| 항목 | 값 |
|---|---|
| 상태 | 실측 |
| 확인일 | 2026-10-03 |
| 제출 | Philip, LAB-A 정리 |
| 영향 | LAB-B 가 주로 겪지만 구조는 모든 랩에 해당 |

## 사실

- 한 turn 안에서 이미 여러 파일과 명령을 처리하고 출력까지 시작한 뒤 쓰던 제공자가 사용 불가가 되면
  NATIVE_CODEX_PINNED_MODEL_UNAVAILABLE 오류가 난다.
- 오류의 취지는 출력이 나간 뒤에는 그 turn 안에서 제공자나 모델을 바꿀 수 없다는 것이다.
  새 turn 을 시작하면 콤보 배차가 다시 돌아 다음 제공자를 고른다.

## 이것이 뜻하는 것

- 콤보 fallback 이 고장난 것이 아니다. 구조상의 제약이다.
- 이 경우 세션을 끝내거나 콤보를 바꾸지 않는다. 새 메시지를 보내면 된다.
- 이미 끝낸 일을 다시 하지 않도록, 새 turn 을 아래 취지로 시작한다.
  이전 작업을 이어서 한다. 지금 파일 상태와 끝나지 않은 항목을 먼저 확인하고 남은 것만 한다.

## 함께 볼 것

- 시작 화면에 콤보 이름이 보여도 실제 준비가 끝났다고 단정하지 않는다.
  필수 환경 변수가 빠져 실행 담당이 멈춘 사례가 있다.
  시작 화면의 콤보 이름만 보고 정상이라고 판단하지 않는다. ADR-0012 의 짧은 시험 단계를 쓴다.
