# FACT-049 ffmpeg 은 명령 창에서 키보드 입력을 기다린다

| 항목 | 값 |
|---|---|
| 상태 | 실측 |
| 확인일 | 2026-10-06 |
| 제출 | LAB-A |
| 영향 | 모든 채널의 렌더와 측정 |

## 사실

ffmpeg 은 돌아가는 동안 키보드 명령을 받는다. 명령 창에서 직접 실행하면
표준 입력을 붙잡고 대화 모드로 들어가, 아무 일도 하지 않은 채 멈춰 있을 수 있다.

2026-10-06 렌더 PC 에서 이것 때문에 장면 하나를 네 시간 넘게 못 끝냈다.
화면에는 장면 시작 줄만 찍히고 더 나아가지 않았다. 중단했을 때 나온 줄이 증거다.

```
Enter command: <target>|all <time>|-1 <command>[ <argument>]
```

## 겉으로 보이는 모습

- 출력 파일이 0바이트로 고정된다.
- ffmpeg 프로세스는 살아 있고 CPU 도 아주 조금씩 오른다. 죽은 것처럼 보이지 않는다.
- 오류도 나지 않는다. 그냥 기다린다.

## 그래서 한다

ffmpeg 을 부를 때 `-nostdin` 을 항상 넣는다. 표준 입력을 보지 않게 하는 옵션이다.

```
ffmpeg -hide_banner -nostdin -loglevel error ...
```

## 왜 전에는 안 걸렸나

같은 스크립트를 실행 담당이 돌릴 때는 표준 입력이 없어서 이 문제가 안 생겼다.
사람이 명령 창에서 직접 돌리면서 드러났다.
**스크립트가 어디서 실행되느냐에 따라 결과가 달라진다.**
