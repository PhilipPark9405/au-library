# 업로드 계획서 스키마

채널과 무관하게 동일한 스키마를 쓴다. 실험실이 바뀌어도 다음 공정이 그대로 받도록 하기 위한 것이다.

```json
{
  "plan_id": "PLAN-2026-0919-econ-01",
  "channel": "econ",
  "publish_at": "2026-09-19T19:00:00+09:00",
  "visibility": "private",
  "title": "",
  "description": "",
  "tags": [],
  "chapters": [
    { "t": "00:00", "label": "" }
  ],
  "lyrics": {
    "present": false,
    "language": "",
    "text": ""
  },
  "timeframe": {
    "longform_sec": 0,
    "short_1_sec": 0,
    "short_2_sec": 0
  },
  "thumbnail_text": "",
  "languages": ["ko"],
  "captions": [],
  "sources": [],
  "notes": ""
}
```

## 규칙

- `visibility`는 처음에 반드시 `private`. 사람이 확인한 뒤 예약 공개로 바꾼다.
- `title`은 100자를 넘기지 않는다.
- `tags`는 15개를 넘기지 않는다.
- `lyrics.present`가 true면 `text`가 비어 있으면 안 된다.
- `sources`에는 본문에 쓴 수치와 인용의 출처 URL을 넣는다. 경제 채널은 비울 수 없다.
- `languages`는 배열이다. 제목과 설명을 여러 언어로 쓰는 채널은 전부 나열한다. 첫 번째가 주 언어다. classic은 ["en", "ko", "ja"]가 된다.

## 사람이 보는 계획서

json 과 별개로, Philip 이 업로드할 때 보는 계획서를 함께 낸다. 2026-09-29 확정.

- 파일 이름은 00_upload_plan.txt 다. 순수 텍스트로 만든다.
- 마크다운으로 만들지 않는다. 뷰어가 번호 목록을 바꿔 순번이 복사되지 않는다. FAIL-2026-0929-001 참조.
- 줄바꿈은 CRLF 로 저장한다.
- 구역은 제목 카드, 이번 판의 특징, 첨부 파일, 롱폼 복붙용, 숏폼 복붙용, 업로드 순서, 24시간 체크리스트, 다음 편 순서다.
- 복사해 붙여넣을 덩어리는 시작과 끝을 표시한다.
- 업로드 설정은 스튜디오 화면 순서대로 항목을 나열한다. 라이선스와 리믹스 설정을 포함한다.
- 24시간 체크리스트에 판정 기준을 숫자로 적는다. 클릭률과 평균 시청 지속시간이다.
- 설명란에는 음원 권리 문구와 영상 소재 출처를 나눠 적는다. 권리 표기는 분량을 이유로 줄이지 않는다.
